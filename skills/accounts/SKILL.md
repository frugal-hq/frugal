# frugal: secondary accounts

Accounts live in `~/.frugal/accounts.json`. While it lists at least one account, frugal exposes the `delegate` tool, adds the delegation rule to each prompt, and sends test runs, long explorations, long edit runs and subagents to those accounts. With none, nothing changes.

Run the matching command with Bash and show its output; `<base>` is this skill's base directory. `add` installs a missing CLI with `npm install -g`; Node.js must be installed first. Antigravity's `agy` is not on npm: `add antigravity` runs Google's installer instead. Successful adds end with a JSON line for Frugal Deck; `status <id>` and `login-command <id>` return one JSON line.

Interactive sign-ins open a terminal that closes itself when the login ends, then check the login and print the result with the signed-in email when known. They wait for the user, so run them with Bash `run_in_background`; when it finishes, show the result and tell the user if the email is not the one they meant. An account stays out of the pool until its login checks out.

- List: `python "<base>/../../accounts/server.py" list`
- Add a Claude login: `python "<base>/../../accounts/server.py" add claude <id>` (its config lives in `~/.claude-<id>`; a login terminal opens)
- Add Codex: `python "<base>/../../accounts/server.py" add codex <id>` (the first account uses the machine login; later accounts use their own `~/.frugal/codex-<id>` home)
- Add Grok: `python "<base>/../../accounts/server.py" add grok <id>` (the first account uses the machine login; later accounts use their own `~/.frugal/grok-<id>` home). Grok never gets heads-up notes, which carry the session transcript.
- Add Antigravity: `python "<base>/../../accounts/server.py" add antigravity <id> [--paid]` (Google's Antigravity CLI, `agy`, signed in with a Google account in the browser; its config and login live in `~/.frugal/antigravity-<id>/.gemini/antigravity-cli`). Antigravity collects interactions for training by default, so it uses the same training gate below; use `--paid` only on a paid Google plan. Antigravity delegates do not take MCP servers yet, and never get heads-up notes, which carry the session transcript.
- Add OpenCode: `python "<base>/../../accounts/server.py" add opencode <id> <provider/model>` (its login and sessions live in `~/.frugal/opencode-<id>`; list models with `opencode models`). It never gets heads-up notes either. Free models need no login. Add one account per model; several are fine.
- Add a pay-per-token API key: `python "<base>/../../accounts/server.py" add api <id> <provider> <model> [--limit <usd> <day|week|month|quarter|year>] [--paid]` (flags in any order). Any provider in the models.dev catalog runs through the OpenCode CLI. A Gemini API key is provider `google` (Gemini CLI accounts are gone: Google ended its personal sign-in on 2026-06-18; a Google login goes through `add antigravity`). Google trains on free-tier API traffic, so an unpaid google key uses the training gate below; `--paid`, accepted only for `google`, marks a key with billing on, the paid tier. List providers, their key variable and the models that can call tools, with prices in USD per 1M tokens (input, output): `python "<base>/../../accounts/server.py" providers` (JSON). Supply the API key on the first line of stdin, never argv; it lives in `~/.frugal/api-<id>/key` and is set on every key variable the provider lists, and the delegate never sees the parent's key for that provider. An old `gemini` account with an API key becomes a `google` api account on its own; one without a key shows in `list` as an unsupported kind and stays out of the pool: remove it. Re-adding the same id replaces the key, model and limit. API accounts are paid, so the recommended order tries them after the free ones for light and standard work; one that reaches its limit leaves the pool until the next period. `list` shows the spend.
- Set or clear the spend limit of an api account: `python "<base>/../../accounts/server.py" limit <id> <usd> <day|week|month|quarter|year>` or `limit <id> off`. Ask the user for the amount; never pick one for them.
- Unpaid google api keys, unpaid Antigravity accounts and OpenCode models that may train on what they receive (Big Pickle, MiMo, Flint, Iceman, Inkling, Nemotron) are blocked by default. Show the setting and those accounts: `python "<base>/../../accounts/server.py" training` (JSON: `mode`, `allowed`, `candidates` with a reason each). Allow all of them: `training all`; only some: `training some <id> [<id>...]`; block again: `training off`. Frugal Deck's Settings set the same. `opencode-training on|off` still works as `training all|off`. Only the user decides this: ask before allowing any.
- Log in again: `python "<base>/../../accounts/server.py" login <id>`
- Remove: `python "<base>/../../accounts/server.py" remove <id>`

After the first account is added, the `delegate` tool appears in the next session (or after `/mcp` reconnects the frugal server).

MCP servers only Claude may use: list their names under `"claude_only_mcp"` in `~/.frugal/accounts.json`. Codex runs get those servers disabled and lose any environment variable carrying the server's name (its token); Grok runs never load Claude's MCP servers or hooks. OpenCode does not read Claude's MCP servers. A task that needs one of the session's MCP servers names it in delegate's `mcp`: it then runs on an account other than Antigravity (only Claude when the server is in `claude_only_mcp`; only the listed kinds when `"mcp_kinds": {"<server>": ["claude", "codex", "grok", "opencode"]}` names the server), which gets just that server and its read-only tools. In Frugal Deck, a server set to "Delegates only" never loads in the chat but can still be named in `mcp`: frugal reads it from the chat's `FRUGAL_DECK_MCP` `delegateOnly` list and lists those names once per session.
